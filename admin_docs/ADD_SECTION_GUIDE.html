Guia real para anadir una seccion nueva en Heaven's Gate

Esta guia no esta escrita para "un PHP cualquiera", sino para esta web tal y como esta montada ahora mismo: un front controller en index.php, un router en app/bootstrap/request_router.php, un dispatcher en app/bootstrap/body_work.php, controladores en app/controllers/..., parciales en app/partials/... y assets en assets/....

Si quieres anadir una seccion y no volver a depender de memoria o de intuicion, sigue este orden. El error mas comun en este proyecto es tocar solo un archivo y asumir que con eso basta. Aqui casi nunca basta.

Advertencia clave: el menu puede renderizarse desde la tabla dim_menu_items. Eso significa que en muchos casos app/partials/main_menu.php no es la fuente real del menu visible. Si anades una seccion y no aparece en navegacion, probablemente te falta alta en base de datos, no en PHP.

1. Mapa mental del sitio

Antes de tocar nada, esto es lo que pasa cuando alguien entra a una URL publica:

  1. La peticion llega a index.php.
  2. app/bootstrap/request_router.php convierte la URL amigable a parametros internos tipo p=....
  3. app/bootstrap/body_work.php mira $_GET['p'] y decide que archivo incluir.
  4. Ese archivo controlador genera el HTML central de la pagina.
  5. index.php envuelve el resultado con cabecera, menu, footer y metadatos, salvo que sea una ruta bare.

Traducido a algo practico: para una seccion normal casi siempre tendras que tocar como minimo 1 controlador, request_router.php y body_work.php. Si quieres que la gente la encuentre, probablemente tambien el menu.

2. Flujo minimo de trabajo

Seccion simple

  1. Crear controlador.
  2. Registrar URL amigable en request_router.php.
  3. Registrar ruta interna en body_work.php.
  4. Anadir metadatos y cargar CSS si hace falta.
  5. Meterla en el menu si debe ser navegable.

Seccion con detalle por slug

  1. Todo lo anterior.
  2. Anadir ruta regex para /seccion/{slug}.
  3. Si usa pretty_id, normalizar en normalize_pretty_request().
  4. Redirigir a slug canonico si aplica.

3. Pasos exactos para anadir una seccion nueva

Paso 1. Decide que tipo de seccion vas a crear

Tipo Ejemplo Donde suele vivir
Pagina principal/listado /gallery, /maps, /players app/controllers/main/, docs/, systems/, etc.
Detalle de entidad /characters/{slug} Controlador propio + routing regex + normalizacion de slug
Tool o pagina bare /ajax/mentions, /maps/api app/controllers/tool/ o app/tools/

Paso 2. Crea el controlador fisico

Haz un archivo nuevo en la carpeta coherente con la familia de la seccion. Si es una pagina publica normal, lo mas normal es una ruta como:

app/controllers/main/main_loquesea.php

Ese archivo debe renderizar el contenido central de la pagina. No tiene que construir el HTML completo del documento; la plantilla base ya la pone index.php.

Paso 3. Si la pagina necesita SEO propio, definelo dentro del controlador

El patron existente es usar setMetaFromPage(...) al principio del controlador.

<?php setMetaFromPage(
    "Mi seccion | Heaven's Gate",
    "Descripcion breve de la nueva seccion.",
    null,
    "website"
); ?>

Paso 4. Si la pagina necesita CSS propio, cargalo dentro del controlador

Patron actual real:

<link rel="stylesheet" href="/assets/css/hg-main.css">

Si la seccion necesita estilos propios, crea algo como assets/css/hg-mi-seccion.css y enlazalo desde el controlador.

Paso 5. Da de alta la URL amigable en app/bootstrap/request_router.php

Aqui hay dos piezas distintas:

  1. La conversion de legacy ?p=... a URL amigable, en hg_request_router_path_from_query().
  2. La conversion de la URL amigable de vuelta a p=..., en hg_request_router_match_path().

Para una seccion simple nueva, normalmente tienes que anadir ambas entradas.

// En hg_request_router_path_from_query()
'mi_seccion' => '/mi-seccion',
// En hg_request_router_match_path(), dentro de $static
'/mi-seccion' => ['p' => 'mi_seccion'],

Paso 6. Da de alta la seccion en app/bootstrap/body_work.php

Este paso es obligatorio. Si no esta aqui, aunque la URL resuelva, la pagina no sabra que archivo incluir.

'mi_seccion' => ['app/controllers/main/main_mi_seccion.php', 'Mi seccion'],

El segundo valor es el nombre de seccion que luego puede aparecer en titulos y metadatos si no los sobrescribes.

Paso 7. Si es una pagina bare, marcalo

Solo aplica a respuestas tipo JSON, snippets embebibles o HTML sin layout global. En ese caso, el route key debe entrar en este array de body_work.php:

if (in_array($routeKey, [..., 'mi_seccion_bare'], true)) {
    $isBarePage = true;
}

Si es una seccion normal visible dentro del sitio, no la metas aqui.

Paso 8. Si tiene acceso desde el menu, anadelo donde toque

Hay dos caminos posibles:

  1. Menu desde base de datos: si existe la tabla dim_menu_items, el menu visible sale de ahi.
  2. Fallback estatico: si no existe esa tabla, se usa app/partials/main_menu.php.

Esto implica una regla importante: editar solo main_menu.php puede no cambiar nada en produccion.

Paso 9. Si quieres que se abra el bloque correcto del menu, revisa hg_menu_open_id_static()

Si la URL pertenece a una familia nueva, puede que necesites mapearla a un bloque como loreMenu, toolsMenu, etc. Si no lo haces, la seccion funcionara, pero el menu lateral no se abrira en el grupo esperado.

Paso 10. Si la seccion usa slugs, pretty_id o detalle por entidad, hay mas trabajo

Eso lo tienes explicado en la seccion 5 de esta guia. No copies el patron de una pagina simple para una pagina de detalle, porque te dejaras la canonicalizacion por slug.

4. Ejemplo completo: anadir /codex-guide

Supongamos que quieres una pagina publica nueva llamada "Codex Guide". El flujo minimo seria este.

4.1 Crear el controlador

app/controllers/main/main_codex_guide.php
<?php
setMetaFromPage(
    "Codex Guide | Heaven's Gate",
    "Internal guide for working with the new site structure.",
    null,
    "website"
);
?>
<link rel="stylesheet" href="/assets/css/hg-docs.css">

<h2>Codex Guide</h2>
<p>Contenido de la nueva seccion.</p>

4.2 Registrar la URL en request_router.php

// hg_request_router_path_from_query()
'codex_guide' => '/codex-guide',
// hg_request_router_match_path() - $static
'/codex-guide' => ['p' => 'codex_guide'],

4.3 Registrar el controlador en body_work.php

'codex_guide' => ['app/controllers/main/main_codex_guide.php', 'Codex Guide'],

4.4 Si quieres un titulo OG base por route key, ampliar setMetaTags()

case 'codex_guide':
    $title = "Codex Guide | Heaven's Gate";
    $description = "Internal guide for working with the new site structure.";
    break;

Esto no siempre es imprescindible si el controlador ya llama a setMetaFromPage(), pero mantiene la logica centralizada y consistente.

4.5 Anadir al menu

Si el menu es de base de datos, mete un registro en dim_menu_items bajo el padre correcto. Si estas en fallback estatico, anade una linea en app/partials/main_menu.php como:

<a href="/codex-guide"><div class="renglonMenu">Codex Guide</div></a>

5. Si la nueva seccion tiene detalle por slug o pretty_id

Aqui es donde suele romperse todo si se improvisa. Las paginas tipo /characters/slug, /players/slug o /documents/slug no usan solo una ruta estatica.

Lo que debes tocar

  1. Una ruta regex en hg_request_router_match_path().
  2. La traduccion inversa en hg_request_router_path_from_query() si hay version legacy.
  3. La normalizacion en normalize_pretty_request() dentro de body_work.php.
  4. El controlador que renderiza el detalle.

Patron conceptual

// request_router.php
'ver_mi_entidad' => '/mi-seccion/' . rawurlencode(...)
// request_router.php - regex
'#^/mi-seccion/([^/]+)$#' => static function (array $m): array {
    return ['p' => 'ver_mi_entidad', 'b' => $m[1]];
},
// body_work.php - normalize_pretty_request()
'ver_mi_entidad' => ['b', 'mi_tabla', '/mi-seccion'],

Ese bloque permite varias cosas:

  • aceptar slug o id;
  • resolver el pretty_id a id interno;
  • redirigir al slug canonico si entra un id o un slug antiguo.

Si tu nueva seccion va a representar entidades con slug, no te saltes este paso.

6. Como meter la seccion en el menu sin volverte loco

Primero: averigua si el menu real sale de base de datos

app/partials/main_menu.php comprueba si existe la tabla dim_menu_items. Si existe, la navegacion sale de ahi. Si no existe, entra el HTML estatico del propio archivo.

Escenario A. Menu en base de datos

Tendras que dar de alta un item en dim_menu_items. Necesitaras al menos:

  • label
  • href
  • parent_id
  • enabled
  • sort_order
  • si es padre: menu_key, iconos, etc.

Si solo quieres anadir una entrada a un bloque ya existente, normalmente bastara con un hijo del padre correcto.

Escenario B. Menu estatico

Anade el enlace en el bloque adecuado de app/partials/main_menu.php.

Escenario C. La seccion funciona pero el menu no se abre en el bloque correcto

Revisa hg_menu_open_id_static() dentro de main_menu.php. Ahi se decide que desplegable debe abrirse segun el path actual.

if (hg_starts_with($path, '/mi-seccion')) {
    return 'loreMenu';
}

7. SEO, CSS, JS y otras piezas que se olvidan siempre

SEO

  • Usa setMetaFromPage() dentro del controlador si la pagina tiene identidad propia.
  • Si quieres consistencia central, ampliala tambien en setMetaTags() de body_work.php.
  • Si la pagina genera un titulo interno importante, usa $pageSect o $pageTitle2 con criterio.

CSS

  • Los estilos base ya vienen desde app/bootstrap/head_work.php: hg-core.css y hg-layout.css.
  • Los estilos especificos de la seccion suelen cargarse desde el propio controlador.
  • Si la nueva seccion es grande, crea su hoja dedicada en assets/css/.

JS

  • El sitio ya carga globalmente permutloading.js, hg-tabs.js y hg-tooltip.js.
  • Si tu seccion necesita JS propio, anadelo explicitamente desde el controlador o reutiliza un script de assets/js/.
  • Si ese JS depende de librerias, confirma si ya existen en assets/vendor/ antes de meter otra copia.

Bare pages y tools

  • Si creas una herramienta tecnica bajo app/tools/, no asumas acceso directo por URL.
  • La carpeta app/ esta bloqueada por reglas del proyecto.
  • Si esa herramienta debe abrirse en navegador, hay que exponerla por front controller y por routing.

8. Checklist final antes de dar la seccion por terminada

  1. Existe un archivo controlador real y carga sin errores.
  2. La URL amigable esta registrada en request_router.php.
  3. El route key esta dado de alta en body_work.php.
  4. La pagina no se ha marcado como bare salvo que de verdad lo sea.
  5. El titulo y la descripcion no son genericos por accidente.
  6. El CSS especifico de la seccion esta cargado.
  7. El menu esta resuelto en el origen correcto: BD o fallback estatico.
  8. El bloque del menu se abre donde toca al entrar en la URL.
  9. Si hay slug, se resuelve y redirige al canonico.
  10. Has probado la URL directa, la navegacion desde menu y un refresh completo del navegador.

9. Script generador para futuras secciones

He dejado un generador en tools/scaffold_section.py. Su objetivo es quitarte la parte mecanica: crear el controlador y dar de alta la seccion en el router y en el dispatcher sin tener que editar tres archivos a mano cada vez.

Convencion importante: usa nombres tecnicos en ingles para mantener el naming del proyecto. Eso afecta a route-key, slug, nombre de archivo del controlador y nombre del CSS. El texto visible al usuario puede seguir en castellano si quieres.

Que hace

  • crea un controlador nuevo en app/controllers/<grupo>/;
  • anade la URL amigable a app/bootstrap/request_router.php;
  • anade el route key a app/bootstrap/body_work.php;
  • puede crear un CSS base en assets/css/;
  • puede anadir un enlace al menu estatico fallback en app/partials/main_menu.php.

Que no hace

  • no resuelve secciones complejas con pretty_id;
  • no toca la tabla dim_menu_items;
  • no inventa consultas SQL ni logica de negocio;
  • no deberia usarse para rutas de detalle tipo /personajes/{slug}.

Ver ayuda

python tools/scaffold_section.py --help

Ejecutar primero en simulacion

python tools/scaffold_section.py ^
  --route-key codex_guide ^
  --slug codex-guide ^
  --title "Codex Guide" ^
  --controller-group main ^
  --css-file hg-codex-guide.css ^
  --create-css ^
  --menu-label "Codex Guide" ^
  --menu-block loreMenu ^
  --dry-run

Ejecutar de verdad

python tools/scaffold_section.py ^
  --route-key codex_guide ^
  --slug codex-guide ^
  --title "Codex Guide" ^
  --controller-group main ^
  --css-file hg-codex-guide.css ^
  --create-css ^
  --menu-label "Codex Guide" ^
  --menu-block loreMenu

Tras eso, el script te deja la base, pero sigues teniendo que entrar al controlador nuevo y sustituir el texto provisional por el contenido real de la seccion.

10. Casos practicos ya pensados

Caso A. Pagina documental simple

Quieres una pagina tipo /admin-guide o /faq. Aqui el script encaja perfecto.

python tools/scaffold_section.py ^
  --route-key faq ^
  --slug faq ^
  --title "FAQ" ^
  --controller-group main ^
  --css-file hg-docs.css ^
  --menu-label "FAQ" ^
  --menu-block startMenu

Caso B. Nueva seccion de trasfondo

Quieres algo tipo /factions que cuelgue del bloque de trasfondo.

python tools/scaffold_section.py ^
  --route-key factions ^
  --slug factions ^
  --title "Factions" ^
  --controller-group main ^
  --css-file hg-factions.css ^
  --create-css ^
  --menu-label "Factions" ^
  --menu-block loreMenu

Luego abres app/controllers/main/main_factions.php y metes las consultas o parciales que necesites.

Caso C. Nueva herramienta publica simple

Si es una pagina normal con layout, todavia puedes usar el script, pero cambiando el grupo de controlador.

python tools/scaffold_section.py ^
  --route-key name_builder ^
  --slug name-builder ^
  --title "Name Builder" ^
  --controller-group tool ^
  --menu-label "Name Builder" ^
  --menu-block toolsMenu

Ojo: esto no la convierte en bare ni en API. Solo crea una pagina publica sencilla servida por el mismo layout general del sitio.

Caso D. Pagina de detalle por slug

Aqui no uses el script tal cual. Para rutas tipo /factions/{slug} tendras que hacer alta manual, porque necesitas regex route, normalizacion en normalize_pretty_request() y politica canonica de slug.

11. Reusable Template

Esta es la plantilla base reutilizable prometida. La idea es que, para una seccion simple, solo tengas que decidir un nombre tecnico en ingles y ejecutar el scaffold. Despues rellenas contenido real.

Regla de naming

  • route-key: ingles, en snake_case. Ejemplo: codex_guide.
  • slug: ingles, en kebab-case. Ejemplo: codex-guide.
  • controlador: ingles, alineado con el route key. Ejemplo: main_codex_guide.php.
  • CSS: ingles, alineado con el slug. Ejemplo: hg-codex-guide.css.
  • texto visible: puede estar en ingles o en castellano, segun lo que quieras mostrar al usuario.

Comando plantilla minimo

python tools/scaffold_section.py ^
  --route-key my_new_section ^
  --slug my-new-section ^
  --title "My New Section" ^
  --controller-group main ^
  --css-file hg-my-new-section.css ^
  --create-css ^
  --menu-label "My New Section" ^
  --menu-block loreMenu ^
  --dry-run

Que te deja preparado

Pieza Resultado
Controlador app/controllers/main/main_my_new_section.php
URL publica /my-new-section
Route key my_new_section
CSS assets/css/hg-my-new-section.css
Menu fallback enlace dentro del bloque que le indiques

Contenido base del controlador generado

<?php setMetaFromPage(
    "My New Section | Heaven's Gate",
    "Nueva seccion publica de Heaven's Gate.",
    null,
    "website"
); ?>
<link rel="stylesheet" href="/assets/css/hg-my-new-section.css">

<h2>My New Section</h2>
<p>Nueva seccion publica de Heaven's Gate.</p>

Flujo recomendado en 2 minutos

  1. Ejecuta el comando con --dry-run.
  2. Si el plan te convence, ejecutalo sin --dry-run.
  3. Abre el controlador generado.
  4. Sustituye el HTML provisional por tu contenido real.
  5. Si el menu real sale de BD, replica la entrada en dim_menu_items.
  6. Prueba la URL directa y la navegacion lateral.

Resumen brutalmente honesto

En esta web, anadir una seccion no consiste en "crear una pagina". Consiste en conectar una pagina al sistema de rutas, al dispatcher y a la navegacion real. Si un dia no recuerdas por donde empezar, piensa en esta secuencia y casi nunca fallaras:

controlador -> request_router.php -> body_work.php -> menu -> SEO/CSS/JS -> pruebas

La version rapida ya la tienes en esta misma guia: plantilla reutilizable, scaffold y naming en ingles para no romper la coherencia del proyecto.
